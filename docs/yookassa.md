# ЮKassa: подписка Полки

Цена: 399 ₽ за 30 дней. Один платёж; продление вручную. Нет сохранения карты и автосписаний.

## Серверные переменные Production

- `YOOKASSA_SHOP_ID`: ID магазина.
- `YOOKASSA_SECRET_KEY`: секретный ключ; добавляется непосредственно в защищённые переменные Vercel. Не коммитить, не включать в NEXT_PUBLIC, не передавать в URL.
- `YOOKASSA_ENABLED=true`: включает оформление только после завершения подключения магазина и коммерческого хостинга.
- `YOOKASSA_TEST_MODE=false`: для живого магазина. Для тестового магазина нужны его ID, тестовый ключ и `true`.
- `APP_URL=https://study-shelf-three.vercel.app`: фиксированный адрес возврата, не принимается от клиента.

Настройки применяются после новой публикации. Сами значения ключей через панель и API не выдаются.

## HTTP-уведомления в кабинете ЮKassa

Интеграция → HTTP-уведомления:

- URL: `https://study-shelf-three.vercel.app/api/billing/webhook`
- События: `payment.succeeded`, `payment.canceled`, `refund.succeeded`.

HTTP Basic Auth требует настройки уведомлений именно в кабинете; регистрация webhook через API предназначена для OAuth. Статус заказа также можно перепроверить после возврата покупателя или кнопкой на странице заказа.

## Устройство интеграции

Сервер фиксирует сумму 399.00 RUB и версию оферты, требует авторизованный аккаунт, принятие оферты и email для чека. UUID заказа служит Idempotence-Key. Оригинал заказа хранится в закрытом Blob, ID — в библиотеке пользователя. Повтор запроса получает тот же платёж. Нельзя проверить или получить чужой заказ.

Покупатель переходит на страницу ЮKassa. Карточные данные Полка не получает. Возврат на сайт сам по себе не даёт подписку: сервер читает платёж через аутентифицированный API, проверяет магазин, сумму, валюту, metadata, test-режим и статус succeeded/paid. Выдача доступа выполняется с CAS и проверкой orderId, поэтому параллельные уведомления не удваивают срок.

Первый успешный платёж даёт 30 дней и свежую квоту 100 ИИ. Продление добавляет следующий период после текущего; квота следующего периода начинается при его активации. Дневной предел 15 не сбрасывается покупкой. После окончания оплаченных периодов чтение, экспорт и удаление данных остаются; новые материалы и платные операции прекращаются. Бесплатный пилот для существующих пользователей не завершается автоматически при добавлении кода интеграции.

Возвраты выполняются владельцем в ЮKassa после обращения в поддержку. Сайт сам не инициирует списаний или возвратов. Событие refund.succeeded перепроверяется через API: каждый refundId учитывается один раз. Проверка заказа также сверяет накопленный refunded_amount, даже если уведомление потеряно. Возвращённая доля сокращает соответствующий период пропорционально сумме; полный возврат отменяет период. Ещё не начавшиеся оплаченные периоды сдвигаются вперёд без потери длительности. Позднее уведомление об успешной оплате не восстанавливает отменённый период. Уведомления ограничены по IP и ID объекта до обращения к провайдеру.

## Чеки НПД

Для самозанятого чек оформляется в «Мой налог» и отправляется на email заказа. ЮKassa не автоматизирует эту операцию. У владельца есть список оплаченных заказов и контакт покупателя. Отметка «чек отправлен» — только фиксация реально выполненного действия; она не формирует чек и не отправляет письмо. Квитанция ЮKassa не заменяет чек НПД.

## Проверки перед включением

1. Активный магазин и действующий ключ подтверждаются живым GET /v3/me из закрытой панели.
2. HTTP-уведомления настроены на указанный URL, три события включены.
3. Vercel переведён на тариф с коммерческим использованием (Hobby для продаж не подходит).
4. Проверьте условия персональных данных, размещения и провайдера ИИ из `docs/commercial-launch.md`.
5. Тестовый магазин: успешная оплата, отмена, повтор callback, повтор запроса и возврат. Фиктивные номера карт нельзя использовать в живом магазине. Для фактического живого контрольного платежа требуется самостоятельное подтверждение владельца; кодовые тесты реальных денег не переводят.

При сетевой ошибке повторяйте тот же заказ. После 23 часов неопределённый заказ без paymentId не создаётся повторно: обратитесь в поддержку для сверки. История ограничена 250 заказами на аккаунт и 50 возвратами на заказ. Документальные основания возврата и сроки указаны на сайте.
